# SQLD Pass 기록 탭 UX 검토 — 2026-09-26

## 결론

기록 탭의 기본 구성은 유지할 수 있다. 다만 **확인 문제 정답률에 모의고사 복습 답안이 섞이는 집계 문제**와 **결과 화면에서 돌아올 때 이력 목록 위치가 초기화되는 문제**를 먼저 수정할 가치가 있다. 빈 상태 문구 정리는 함께 적용할 수 있는 작은 개선이다.

## 확인 대상과 범위

- 실제 휴대폰: Samsung SM-F721N, 1080×2640, density 480.
- 설치본: `com.sqldpass.app.internal`, 0.1.0 / versionCode 1, 업데이트 2026-09-26 21:28:51 KST. 앞선 실전 탭 개선을 반영한 검증용 앱이다.
- Play 패키지 `com.kasa500000.sqldpass`는 설치되어 있지 않았다. 이번 관찰은 스토어 배포본 직접 검증이 아니다.
- 소스: `main`의 `edb768c`. APK SHA-256: `eb3cabcd7435dc61e8303ebc77545e89caff04cbacbb6ce704e839d82d94f812`.
- 휴대폰에는 풀이·응시 기록이 없었다. 기록 탭 전체, 아래로 스크롤, 실전 모의고사 이동, 설정 왕복, 글자 크기 100%·130%를 확인했다. 두 배율 모두 마지막 버튼까지 화면에 들어왔고 아래 스크롤 후에도 위치가 같았다.
- 누적 기록은 별도 Android 에뮬레이터(1080×2400, density 420)에 동일 APK를 설치하여 검증했다. 무료 M01·M02를 미응답으로 제출한 샘플 2건과 M01-Q01 복습 답안 1건을 UI로 생성했다. 실제 사용자 성적이 아니며 휴대폰에는 샘플 기록을 만들지 않았다.
- 별도 메모리 기반 컨트롤러 재현에서도 집계 문제를 확인했다. 실제 광고·배너, iOS·태블릿, TalkBack 음성, 대량 이력 성능 및 재응시 여러 건의 표시 검증은 포함하지 않는다.

## 권장 개선

| 우선순위 | 관찰한 문제 | 사용자 영향 | 권장 변경 |
|---|---|---|---|
| 높음 | 모의고사 복습 1문항을 맞히면 확인 문제를 풀지 않았어도 `확인 문제 · 첫 풀이`에 정답률 100%가 표시된다. | 이론 확인 문제의 성취도를 잘못 이해할 수 있다. | 확인 문제에 속하는 문항 ID만 대상으로 첫 답안을 집계한다. 모의고사 성적과 복습 답안은 이 지표에서 분리한다. |
| 중간 | 아래쪽 응시 이력에서 `결과·해설 보기` → 헤더 뒤로를 누르면 기록 탭 상단으로 돌아온다. | 여러 결과를 비교할 때 다시 스크롤해야 한다. | 기록 목록도 학습·실전 목록처럼 실행 중 탐색 위치를 보존한다. |
| 낮음 | 풀이 기록이 없는 카드에 `확신 정답 비율 —`가 남는다. 기록이 있을 때 집계 문항 수는 `계산 기준`을 눌러야 보인다. | 빈 화면에서 의미 없는 지표를 읽고, 1문항의 100%와 여러 문항의 100%를 바로 구분하기 어렵다. | 빈 상태에서는 미산출 지표를 생략한다. 기록이 있으면 풀이 문항 수를 정답률 옆에 짧게 표시한다. |

권장 순서는 **집계 범위 수정 → 기록 목록 복귀 → 빈 상태·표본 수 정리**다. 그래프, 메뉴, 새 분석 화면을 추가할 필요성은 이번 검토에서 확인되지 않았다.

### 1. 정답률 집계 문제 재현

1. 확인 문제 풀이 기록이 없는 테스트 상태에서 M01을 미응답으로 제출했다.
2. 학습 → 복습에서 `SQLD-M01-Q01`의 `이 문항 복습`을 열었다.
3. 정답을 선택하고 `정답 확인` → `연습 결과 확인`을 눌렀다.
4. 기록 탭에 `첫 풀이 정답률 100%`, `확신 있게 맞힌 비율 100%`가 나타났다.
5. 계산 기준은 `1문항의 첫 답안 기준`으로 표시됐다. 그 1문항은 이론 확인 문항이 아닌 모의고사 문항이다.

원인은 `src/ui/learning-polish.ts:177` 이후의 첫 답안 집계가 모든 `state.responses`를 사용하기 때문이다. `src/core/domain/review.ts:19`의 확신 비율 계산도 같은 전체 응답을 사용한다. 모의고사 제출 후 복습은 정상적으로 이 응답 배열에 저장되므로 지표의 제목과 집계 대상이 일치하지 않는다.

**복습 모드 전체를 제외하면 안 된다.** 이론 확인 문제를 복습한 답안도 같은 모드를 사용한다. 확인 문제의 실제 문항 ID를 기준으로 범위를 정하고, 그 범위 안에서 최초 답안 1건만 사용해야 한다. 기존 답안·복습 일정·저장된 모의고사 점수를 삭제하거나 바꿀 필요는 없다.

독립 재현 자료: `.build/records-audit-model.cjs` / `.build/records-audit-model.json`. 출력은 확인 문제 응답 0건, 모의고사 복습 응답 1건, 화면 정답률 100%다. 이 스크립트는 장치나 앱 데이터 파일에 쓰지 않는다.

### 2. 목록 복귀 문제 재현

- 테스트 응시 이력 2건이 최신순으로 표시되는 것을 확인했다.
- 아래로 스크롤하여 M01의 결과 버튼 `[98,1855][984,1991]`을 눌렀다.
- M01 결과가 열리는 것을 확인하고 헤더 뒤로를 눌렀다.
- 기록 탭의 `학습 기록` 제목 Y=356px가 다시 표시됐다. M01 결과 버튼은 화면 밖으로 내려갔다.
- `src/ui/learning-polish.ts:216` 이후에서 탐색 위치 복원은 `catalog`와 `exams`에만 연결되어 있다. `stats`에는 연결되지 않았다.

## 유지해도 좋은 부분

- 상단 학습 요약 → 확인 문제 통계 → 모의고사 이력의 순서를 이해하기 쉽다.
- 휴대폰의 빈 상태는 100%·130% 모두 제목·숫자·버튼이 정상 표시됐다. 남는 여백을 채우기 위한 카드 추가는 필요하지 않다.
- `실전 모의고사 보기`는 실제 회차 목록으로 이동한다.
- 샘플 응시 2건은 최신순이며, 결과 버튼은 해당 회차의 저장된 결과를 연다.
- 이론의 읽음 수는 명시적 읽음 완료 기준으로 집계된다. 단순히 본문을 열었다는 이유로 완료 수를 올리는 변경은 권장하지 않는다.
- 휴대폰과 에뮬레이터의 현재 앱 프로세스 logcat에서 FATAL EXCEPTION / AndroidRuntime / ReactNativeJS 오류 패턴을 찾지 못했다.
