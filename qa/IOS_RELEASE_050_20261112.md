# iOS 0.5.0(16) 출시 기록

## 이번 버전의 검증 생략 예외

소유자는 40회 후보의 iOS 추가 검증·제출이 남은 상태에서 “검증 생략 예외로 ios도 정식 심사 및 testflight 업데이트 반영”이라고 지시했다. 이 지시는 0.5.0(16)의 추가 물리 iPad·동의 재검증에 적용한다. 미실행 검사는 통과로 표시하지 않으며, 이전 0.4.0 예외를 재사용하지 않았다. [AGENTS.md](../AGENTS.md)에 새 범위를 기록했다.

기존 현재 후보의 471개 자동 검사, Android 실기기, iPhone·iPad 시뮬레이터, SQLite 업데이트/불변 스냅샷 대조, 공식 테스트 보상 및 눈에 보이는 EEA 동의 화면의 거부·허용·철회 결과는 [40회 검증 기록](MOCK40_20261112.md)에 있다. 시뮬레이터와 Android 결과는 iPad 실기기 검증이 아니다. 이번 제출 작업에서 기능·데이터 이관·동의·보상 조건은 변경하지 않았다.

## 스토어 준비

- 설명·업데이트·심사 메모에 40회 재편, 이전1권 정리, 남기는 기록 보존 및 무료10회를 명시했다. 기존 심사 연락처와 데이터 수집 신고는 유지한다.
- iPhone6.5형1284×2778와 iPad2064×2752에서 현재 앱의 홈·교재·문제·새1권·새2권을 직접 캡처했다. iPhone은 다크, iPad는 라이트다. 두 캡처 실행이 성공했고 이미지를 직접 확인했다. 이 작업은 스토어 이미지 준비이며 별도 기능·실기기·동의 재검증 통과로 계산하지 않는다.
- 업로드 전 기존0.4.0(15)은 `WAITING_FOR_REVIEW`, 공개0.3.4는 `READY_FOR_SALE`이었다. 새 빌드의 Apple 처리 완료 후 기존 대기 제출을 취소하고 같은 버전 레코드를 0.5.0으로 교체했다. 중간 `DEVELOPER_REJECTED`는 개발자 취소 결과이며 Apple 심사 거절이 아니다. 공개 중인 앱은 유지하며, 새 제출은 심사 대기열을 다시 시작한다. [Apple 제출 취소 안내](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/remove-a-submission-from-review).

- Apple 처리 `VALID`, 배포 대상 `APP_STORE_ELIGIBLE` 확인. 18:03 KST 기존 **SQLD Pass 내부 검증** 그룹에 빌드16을 추가했고 `IN_BETA_TESTING`, 자동 알림 활성화를 확인했다. 외부 테스터 그룹의 별도 베타 심사는 수행하지 않았다. [TestFlight 증거](evidence/ios-release-050-20261112/testflight.json).

[제출 증거](evidence/ios-release-050-20261112/app-store-submission.json), [최종 서버 상태](evidence/ios-release-050-20261112/final-server-state.json).
