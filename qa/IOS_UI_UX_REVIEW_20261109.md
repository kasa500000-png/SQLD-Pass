# SQLD Pass iOS UI·UX 검토 — 2026-11-09

현재 앱은 새 교재와 모의고사를 네이티브 화면에서 이용할 수 있고, 본문·표·해설의 표현 기반도 갖췄다. 그러나 전문 학습 앱의 완성도로 평가하면 **콘텐츠를 담는 기능에 비해, 학습자의 다음 행동을 안내하는 화면 설계가 부족하다.** 전면적인 색상 변경보다 버튼의 역할 구분, 시험 조작의 고정 배치, 결과와 복습의 분리부터 개선하는 것이 효과적이다.

이 문서는 실제 시뮬레이터 조작에 기반한 전문가 관점의 휴리스틱 평가다. 사용자 조사, 전환율 측정, App Store 승인 판정은 아니다. 제안한 UI는 아직 구현하지 않았다.

모든 216절·1,000개 모의고사 문항·37개 체험 도구를 전수 조작한 것은 아니다. 체험 도구는 표의 행·열·값 선택 대표 사례를 확인했다. VoiceOver 실제 낭독, 시스템 최대 Dynamic Type, 작은 iPhone, iPad 분할 창, 키보드 입력·메모 저장, 실기기 알림 도착, 성능·배터리·색상 대비 수치 검증은 수행하지 않았다. 앱 내 글자 크기 130% 확인은 시스템 접근성 글자 크기 검증을 대체하지 않는다. 검토 과정의 답안·응시 기록은 내부 시뮬레이터 테스트 데이터다.

## 유지할 강점

- **학습 구조가 분명하다.** 홈·교재·문제·실전·기록의 다섯 영역과 Part → Chapter → Section 구조는 새 콘텐츠에 적합하다.
- **본문 읽기 기반이 좋다.** 긴 문장, SQL, 표, 강조 블록을 네이티브로 표현하며, iPad 본문은 읽기 폭이 제한되어 있다. 태블릿 전체 화면에 문단을 끝까지 늘리지 않은 점은 유지한다.
- **상태를 정직하게 표시한다.** 읽은 절, 풀어본 문제, 최근 답안 정답률, 실전·학습 모드 기록이 구분된다. 합격 가능성을 임의로 계산하지 않는다.
- **시험 제출 안내가 명확하다.** 미응답 수와 제출 후 답안 변경 불가를 확인 창에서 안내한다. 학습 모드도 제출 후 해설을 확인하는 일관성이 있다.
- **연결된 학습 자료가 풍부하다.** 해설에서 관련 이론으로 이동하고 문항을 저장할 수 있다. 대표 표 체험에서는 선택한 셀의 강조와 설명이 대응했다.
- **기본 시각 언어는 일관적이다.** 블루 계열, 라이트·다크 표면, 둥근 카드, 하단 탭의 통일성은 유지할 가치가 있다.

## 우선 개선 사항

P1은 핵심 학습 동선에서 먼저 해결할 항목, P2는 사용성과 완성도를 높일 항목, P3는 후속 세부 개선이다. P1이라는 표기는 곧바로 스토어 심사 거절 사유라는 뜻이 아니다.

### P1-01. 모의고사 시작 버튼이 긴 설명 아래에 있다

**관찰:** 실전 → 회차 → 응시 안내의 첫 화면에 제목이 두 번 나오고, 채점 안내와 여러 시험 전제가 길게 이어진다. 100% 글자 크기에서도 실전/학습 시작 버튼이 첫 화면에 보이지 않는다. [증거 09](evidence/ios-ux-review-20261109/09-iphone-exam-intro.png)

**영향:** 사용자가 시험을 시작하기 전에 문서 전체를 훑어 내려야 한다. 이용 조건과 시작 행동의 우선순위가 뒤바뀌어 있다.

**권장:** 회차 제목 → 50문항·90분 요약 → 실전/학습 모드 선택 → 핵심 규칙 → 하단 고정 시작 버튼 순으로 재구성한다. DBMS·정렬·검산·출처 관련 원문은 삭제하지 않고 ‘응시 기준 자세히’에 유지한다. 학습 모드의 무제한 시간과 제출 후 해설 공개도 명확히 표시한다.

**완료 기준:** 기본 글자 크기 첫 화면에서 모드와 시작 동작을 찾을 수 있고, 큰 글자에서도 시작 버튼이 내용에 가려지지 않는다. 상세 시험 전제에는 쉽게 접근할 수 있다.

### P1-02. 시험 조작이 문제 본문과 함께 스크롤된다

**관찰:** 타이머·모드·응답 수·문항 번호가 세로 공간을 많이 차지한다. 짧은 첫 문항에서도 다음/답안표 버튼이 첫 화면 아래에 있다. 표와 SQL이 있는 문항에서는 이동 거리가 더 길어진다. 설정과 전체 하단 탭도 시험 중 계속 보인다. [증거 10](evidence/ios-ux-review-20261109/10-iphone-timed-exam.png), [증거 12](evidence/ios-ux-review-20261109/12-iphone-table-question.png)

**영향:** 50문항을 푸는 동안 같은 스크롤을 반복하고 남은 시간 확인도 번거롭다. 답안 지우기 같은 보조 기능이 다음 문제보다 눈에 먼저 들어온다.

**권장:** 상단에 문항 번호·남은 시간을 간결하게 고정하고, 하단에 이전·답안표·다음을 고정한다. 검토 표시와 답안 지우기는 보조 액션으로 줄인다. 시험 중에는 전역 탭 대신 ‘저장 후 나가기’가 분명한 집중 화면을 권장한다. 이는 현재의 항상 보이는 다섯 탭 규칙을 시험 화면에 한해 수정하는 제안이다. 타이머 지속·재진입·저장·광고 억제 정책은 그대로 유지한다.

**완료 기준:** 긴 SQL·표 문제에서도 화면 위치에 관계없이 다음/이전/답안표에 접근한다. 고정 바가 마지막 선택지를 덮지 않고, 나갔다 돌아와도 답안·시간이 일관된다. 학습 모드에는 잘못된 카운트다운을 표시하지 않는다.

### P1-03. 결과 요약과 문항 해설이 한 화면에 과도하게 섞여 있다

**관찰:** 점수 요약 뒤에 첫 문항, 선택지, 정답, 보기별 근거, 관련 이론, 저장, 메모, 검산 설명이 이어지고 다음 해설 이동은 아래에 있다. [증거 13](evidence/ios-ux-review-20261109/13-iphone-result.png), [증거 14](evidence/ios-ux-review-20261109/14-iphone-explanation-bottom.png)

**영향:** 자신의 약점을 파악하는 일과 개별 문항을 읽는 일이 섞인다. 여러 해설을 빠르게 비교하기 어렵다.

**권장:** 결과는 점수·과목별 성적·정답/오답/미응답 수·복습 시작 중심으로 구성한다. 해설은 별도 문항 뷰에서 제공하고 이전/다음과 문항 선택기를 고정한다. 필수 정답 근거는 바로 읽게 하고 메모·추가 검산 근거는 접을 수 있게 한다. 원문, 보기별 해설, 제출 당시 스냅샷은 보존한다.

**완료 기준:** 결과에서 오답 복습을 바로 시작하고 임의 문항으로 이동할 수 있다. 긴 해설을 끝까지 내려가지 않고도 다음 문항을 연다. 복습이 원래 시험 점수를 변경하지 않는다.

### P1-04. 버튼의 중요도와 정오답 상태가 충분히 구분되지 않는다

**관찰:** 메뉴 이동, 답안 선택, 설정 선택, 저장, 시험 제출에 비슷한 연한 파랑 전체 폭 버튼을 사용한다. 확인문제 오답 제출 후 선택한 오답은 파란 선택 상태로 남고 정답 보기는 별도로 강조되지 않는다. 정답은 아래 설명에서 찾아야 한다. [증거 02](evidence/ios-ux-review-20261109/02-iphone-setup.png), [증거 06](evidence/ios-ux-review-20261109/06-iphone-practice-feedback.png)

**영향:** 무엇을 먼저 눌러야 하는지, 제출한 답이 왜 틀렸는지 한눈에 판단하기 어렵다. 긴 보기의 가운데 정렬도 줄별 읽기 시작점을 흔든다.

**권장:** 주요 실행은 채운 버튼, 보조 실행은 옅은 버튼/테두리, 이동은 좌측 정렬 목록 행과 화살표, 상태 선택은 세그먼트/칩, 답안은 번호와 본문을 분리한 좌측 정렬 선택 카드로 구분한다. 제출 후에는 ‘내 답·오답’, ‘정답’을 아이콘·문구·색으로 함께 표시한다. 삭제는 위험 동작임을 별도로 표현한다.

**완료 기준:** 각 화면의 대표 실행을 시각적으로 식별할 수 있고, 색을 구분하지 못해도 정답과 오답을 알 수 있다. 선택 상태와 채점 상태가 구분된다. 시험 중에는 정답을 미리 드러내지 않는다.

### P1-05. 학습 알림 오류의 원인과 해결 경로가 불분명하다

**관찰:** 설정 → 학습 알림에서 OFF 상태인데도 ‘알림 예약을 확인하지 못했어요’ 및 오류 문구가 표시됐다. ‘다시 시도’를 한 차례 실행해도 같은 오류가 남았다. [증거 16](evidence/ios-ux-review-20261109/16-iphone-reminder-error.png)

**판단 범위:** 이 내부 iOS 시뮬레이터에서 확인한 증상이다. 실기기·배포 앱에서도 동일한지와 원인은 확인하지 않았다. 권한 문제, 시뮬레이터 환경, 네이티브 연결 문제 중 어느 것인지 단정하지 않는다.

**권장:** 실제 알림 상태와 네이티브 오류 로그를 확인한 뒤 ‘꺼짐’, ‘권한 거부’, ‘예약 실패’, ‘현재 환경에서 사용 불가’를 구분한다. 권한 문제에는 설정 이동, 일시 실패에는 재시도 등 원인에 맞는 복구 방법을 제공한다.

**완료 기준:** OFF가 정상 상태라면 오류로 오인시키지 않는다. 실제 기기에서 허용·거부·재허용·예약·앱 재시작·알림 도착을 확인하고, 실패 시 실행 가능한 안내가 나온다.

## 디자인 시스템에 반영할 방향

색상 팔레트를 버리기보다 현재 토큰 위에 **역할별 컴포넌트 규칙**을 보강한다. 현재 공통 버튼만으로 목록·선택지·실행·필터를 표현하는 방식을 줄이는 것이 핵심이다.

| 컴포넌트 역할 | 권장 표현 |
|---|---|
| 주요 실행 | 한 화면에서 중심 행동이 식별되는 채운 버튼. 시작·답안 확인·다음 학습 등 |
| 보조 실행 | 낮은 강조의 버튼. 저장·나중에·설명 보기 등 |
| 목록 이동 | 제목·보조 정보·상태·화살표가 있는 좌측 정렬 행 |
| 단일 상태 선택 | 모드·테마·필터용 세그먼트 또는 선택 칩 |
| 답안 | 번호와 내용 분리, 줄바꿈 가능한 좌측 정렬, 선택/정답/오답의 별도 상태 |
| 시험 조작 | 고정된 시간·문항 헤더와 안전 영역을 고려한 하단 이동 바 |
| 학습 결과 | 성적 요약과 다음 학습 액션. 상세 해설은 별도 탐색 구조 |
| 빈 상태·오류 | 현재 이유와 다음 행동. 단순히 0건 또는 실패 문구만 표시하지 않음 |

타이포그래피는 화면 제목, 문항 지문, 본문, 보조 정보, SQL의 역할을 구분한다. 긴 지문 전체를 과하게 굵고 크게 처리하면 필요한 비교 정보가 밀리므로 짧은 제목과 읽을 본문을 구분한다. 화면 제목 반복, 카드 안팎의 중복 여백도 함께 줄인다. 여백을 줄이더라도 터치 영역과 큰 글자 지원은 유지한다.

Apple은 주요 버튼의 시각적 강조를 제한하고 역할에 맞는 스타일을 권장한다. 위 계층 구분의 참고 근거이며, 구체적인 화면 재배치는 이 앱에 대한 평가자의 제안이다. [Apple HIG: Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)

터치 영역은 프로젝트의 **48pt 이상** 규칙을 유지한다. Apple의 일반적인 최소 44×44pt 안내보다 엄격한 기존 기준을 낮출 이유는 없다. 이번 검토에서 모든 버튼의 실제 히트 영역을 측정한 것은 아니다. [Apple UI Design Tips](https://developer.apple.com/design/tips/)

태블릿은 기기 이름이 아니라 사용 가능한 창 폭에 맞춰 재배치한다. 이번 가로/세로 확인에 더해 분할 창 검증이 필요하다. [Apple: View layout](https://developer.apple.com/documentation/uikit/view-layout)

## 권장 적용 순서와 검증 기준

1. **시험·복습 동선:** 응시 안내, 시험 고정 조작, 결과/해설 분리, 정오답 피드백을 먼저 개선한다. 타이머·답안 스냅샷·채점·보상 정책은 UI 변경과 분리해 보존한다.
2. **공통 컴포넌트:** 버튼·목록 행·선택지·세그먼트·빈 상태를 정리하고 홈/목차/설정에 적용한다. 새로운 디자인 규칙은 `docs/UI_DESIGN_REFERENCE.md`와 디자인 스킬에 함께 반영한다.
3. **학습 안내:** 중복 이어하기를 정리하고 완료→복습→관련 이론의 다음 행동을 연결한다. 실제 로컬 데이터만 사용한다.
4. **iPad·접근성·오류:** 폭별 재배치, 시스템 큰 글자, VoiceOver, 키보드, 알림 실기기 검증을 마무리한다.

변경 후 검증은 짧은 이론·긴 이론·표·SQL·긴 선택지·오답·미응답·검토 표시·저장 없음·검색 결과 없음·진행 중·완료·오류 상태를 포함한다. 대표 경로는 ‘새 사용자 첫 학습’, ‘이어서 읽고 확인문제’, ‘90분 시험의 저장 후 재진입과 제출’, ‘학습 모드 제출’, ‘오답에서 관련 절로 이동’, ‘저장·메모 후 복귀’다. 실기기에서 라이트/다크, 앱 글자 크기와 시스템 큰 글자 조합, iPad 좁은 창도 확인해야 한다.

정량 효과는 아직 측정하지 않았다. 적용 전후에 시험 시작까지의 탐색, 문제당 이동 조작, 결과에서 특정 해설까지의 접근, 빈 상태의 다음 행동 발견 여부를 같은 과제로 비교하면 개선 효과를 검증할 수 있다.
