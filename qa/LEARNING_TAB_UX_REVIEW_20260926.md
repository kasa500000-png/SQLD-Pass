# SQLD Pass 학습 탭 UX 검토 — 2026-09-26

## 결론

현재 카드 디자인과 이론·복습·북마크 구성을 유지하면서 **목록 복귀 위치 소실과 복습 화면의 잘못된 이동을 우선 수정**할 것을 권장한다. 두 동작은 실제 기기에서 재현됐고 반복 학습을 방해한다. 읽는 중 표시와 빈 북마크 안내는 함께 정리할 만한 작은 개선이다.

## 확인 범위

- 실제 연결 기기: Samsung SM-F721N, 1080×2640, density 480.
- 설치본: `com.sqldpass.app.internal`, 0.1.0 / versionCode 1, 마지막 업데이트 2026-09-26 18:40:33. 앞선 홈 개선을 반영한 검증용 앱이다. 현재 Play/App Store 프로덕션 설치본의 상태를 확인한 것으로 해석하지 않는다.
- 소스 기준: `cc03342`. 이번 작업에서 앱 소스는 수정하지 않았다.
- 이론 목록 상단에서 60번 끝까지 이동하며 화면을 캡처했다. 수집한 UI 트리에 SQLD-L001~L060의 60개 목록 항목이 모두 존재함을 확인했다.
- 전체/1과목/2과목 필터, 검색 성공/검색 결과 없음/초기화, 이론 진입·뒤로 가기, 북마크 없음/임시 저장/해제, 복습 빈 화면 및 이론 이동, 글자 크기 100%/130%를 확인했다.
- 현재 기기는 복습 문항이 없는 상태다. 누적 복습 목록과 실제 복습 채점, iOS·태블릿 화면은 이번 실기기 검토 범위에 포함하지 않았다.

|---|---|---|---|
| 높음 · 1 | 목록 중간에서 7번 이론을 열고 바로 뒤로 가면 1번이 있는 최상단으로 이동한다. 60번 진입 후 복귀에서도 동일했다. | 다음 이론을 이어서 고를 때 매번 원래 보던 곳까지 내려가야 한다. | 이론에서 돌아올 때 목록의 보던 카드 위치를 복원한다. 기존 본문 읽기 위치 저장과 목록 탐색 위치를 구분한다. |

추천 순서는 **1·2 수정 → 3·4 상태 문구 정리 → 같은 동선 재검증**이다.

## 디자인 평가

- 제목, 번호, 과목, 예상 시간, 읽음/확인 문제 진도의 위계가 분명하다. 확인한 화면에서 글자가 카드 밖으로 잘리거나 하단 탭이 가려지는 문제는 없었다.
- 100%에서 첫 화면은 이론 3개와 다음 항목 일부, 130%에서는 3개 정도가 보인다. 130%에서도 제목과 진도가 줄바꿈되어 읽힌다.
- 목록 중간은 카드만 보여 밀도가 높아지고 검색·과목 필터·이론/복습/북마크 선택은 위로 스크롤되어 사라진다. 보조 개선으로 상단 선택 영역을 고정하거나 여백을 줄일 수 있으나, 우선순위는 실제 이동 오류보다 낮다.
- 57번 등 긴 영문 제목은 여러 줄로 펼쳐져 카드 높이가 커진다. 내용을 읽을 수 있으므로 이번 우선 수정 사유로 보지는 않는다.
- 추가 통계 카드, 새 탭, 설명 문구 확대 또는 학습 구조 전면 변경은 이번 관찰에서 필요성이 확인되지 않았다.

## 정상 작동 확인

- 과목 필터: 전체 60개 / 1과목 14개 / 2과목 46개.
- 2과목에서 `NULL` 검색: 31개 결과. 제목에 없는 본문 키워드도 검색되는 현재 동작과 일치한다.
- 결과 없는 검색과 ‘검색·필터 초기화’로 전체 목록 복귀.
- LESSON 60을 임시 북마크로 저장하면 북마크 목록에 1개 표시. 해제 후 0개로 돌아오는 것 확인.
- LESSON 01 본문은 이전에 저장한 중간 위치로 정상 복원. 이번 목록 위치 문제와는 별개다.

## 구현 검토 근거

- `src/ui/learning-polish.ts:112`: 복습 빈 화면의 동작은 `c.tab('learn')`만 호출하여 기존 `bookmarkedOnly` 상태가 남는다. 같은 파일의 ‘이론’ 선택 동작은 이를 false로 만든다.
- `src/ui/learning-polish.ts:206`, `src/platform/NativeView.tsx`: 경로별 스크롤 키를 사용하고 본문 복원은 lesson 경로에만 연결되어 있다. 목록은 다시 생성되며 탐색 위치를 저장하지 않는다.
- `src/ui/learning-format.ts:18`: `lessonStatus`는 읽음 완료 여부만으로 ‘읽음/읽기 전’을 결정한다. 새로 추가된 reading 상태를 아직 반영하지 않는다.
- 검토 결론은 기기에서 관찰한 동작을 먼저 기준으로 삼고 해당 코드로 원인을 교차 확인했다.
