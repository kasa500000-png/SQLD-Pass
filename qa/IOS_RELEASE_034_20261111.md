# iOS 0.3.4(14) 출시 준비 기록

2026-11-11. 소유자는 TestFlight 업데이트와 정식 제출을 재차 지시했다. 이후 iPad 잠금 차단을 안내받고 “이번에도 예외로 진행”이라고 명시했다. 이번0.3.4(14)에 한해 추가 iPad·동의 재검증 없이 제출한다. 실제 빌드·서명·업로드 처리, 콘텐츠 승인과 런타임 동의·보상 조건은 유지한다.

## 수행한 작업

- Apple API에서 현재 공개 버전0.3.3(13), 새0.3.4 초안 `PREPARE_FOR_SUBMISSION`, 승인 후 자동 출시 `AFTER_APPROVAL`을 확인했다.
- 새 기능 설명, 교재·광고 설명과 심사 메모가0.3.4(14)에 맞는지 확인했다. 기존 개인정보 신고·스크린샷·심사 연락처를 유지했다.
- Google Drive의 암호화 백업에서 서명 자료를 복구하고 백업 해시·배포 인증서·프로비저닝을 확인했다. 비밀 자료는 저장소에 포함하지 않았다.
- iPad가 다시 연결되어 별도 공식 테스트 광고 앱0.3.4(14), `com.sqldpass.app.internal`을 설치했다. 운영 앱과 기존 학습 데이터를 초기화하지 않았다.
- 물리 기기 XCTest 실행기를 빌드·서명했다. 기기가 잠긴 상태로 실행 대기한 뒤 `Lost pending connection to the test runner before launch`로 종료됐다. 앱의 학습·광고 동작 검사는 시작되지 않았다.
- 운영 archive/export/upload, TestFlight 기존 내부 그룹 추가 및 새 버전 정식 심사 전송 절차를 준비했다. 아직 실행하지 않았다.

## 검증 범위와 예외

기존436개 자동 검사, Android 실기기와 iOS 시뮬레이터 결과는 [통합 보고](UI_FOCUS_034_20261111.md)에 있다. 이번 iPad 설치 성공은 실기기 동작·광고·동의 검사 통과를 의미하지 않는다. 현재 코드 해시에 맞춘 [iOS 승인 기록](../release/history/ads-release-approval.ios.ui-focus-20261111.json)에 새 소유자 예외, 이번 검증, 과거 동의 증거를 구분해 적었다. 이전 Android 승인 이력은 보존한다.

추가 iPad의 중지·재개·최종 제출·기록 유지와 테스트 광고·지역별 동의 재실행은 생략한다. 시뮬레이터·Android 결과를 iOS 실기기 결과로 바꾸지 않는다. 운영 빌드14의 archive/export, Apple 업로드 처리, TestFlight 내부 그룹 추가와 App Store 정식 심사 제출은 실제 결과를 아래에 기록한다.

0.3.3의 예외를 전용한 것이 아니라 이번0.3.4에 대한 새 소유자 지시다. `AGENTS.md`에 버전 한정 예외를 추가했다. 이후 버전의 검증 규칙은 유지한다.

예외 지시 전22:14 KST 관찰에서는 최신 업로드13, 새14 없음, 정식 제출 미완료였다. [당시 서버·설치 관찰 기록](evidence/ios-release-034-20261111/preparation.json)은 과거 상태로 보존한다.

## 실행 결과

- Release archive 및 App Store export 성공. 최종 IPA는0.3.4(14), 운영 bundle `com.kasa500000.sqldpass`다.
- archive와 내보낸 IPA의 코드 서명을 각각 검사했다. 배포 entitlement는 `F4HJ438953.com.kasa500000.sqldpass`, `get-task-allow=false`다.
- 실제 IPA의 production/live/rewarded 설정, 운영 iOS AdMob 앱·배너·보상 ID, 새 교재 승인 해시와 개인정보 manifest 포함을 확인했다. ATT 설명 키는 없으며 원격 학습 분석은 꺼져 있다. [배포 파일 검사](evidence/ios-release-034-20261111/artifact.json).
- 23:50 KST Apple 업로드 성공. Delivery UUID `0c86953c-66f7-4bbc-999d-3a4a909e53ab`,19,027,317bytes. 업로더의 로컬 재시작 파일 경고 뒤 종료코드0과 `UPLOAD SUCCEEDED with no errors`를 확인했다. Apple 서버 처리 결과는 별도로 확인한다. [업로드 receipt](evidence/ios-release-034-20261111/upload.json).
- Apple 처리 `VALID`, `APP_STORE_ELIGIBLE` 확인. 동일 빌드14를 TestFlight 기존 **SQLD Pass 내부 검증** 그룹에 추가했으며 `IN_BETA_TESTING`, 자동 알림 활성화 상태다. [TestFlight receipt](evidence/ios-release-034-20261111/testflight.json).
- 2026-11-11 **23:54 KST** App Store 정식 심사 제출 완료: `WAITING_FOR_REVIEW`. 승인 후 자동 출시 `AFTER_APPROVAL`이며 새 제출 ID는 `73cab924-16fc-4bf8-8512-898b6cf5c47b`다. [정식 제출 receipt](evidence/ios-release-034-20261111/app-store-submission.json).
- 제출 시점 공개 버전0.3.3(13)은 유지했다.0.3.4의 심사 승인·공개 출시는 아직 완료되지 않았다.
- 운영 광고 설정이 포함된 배포 빌드이며 새 실기기의 실제 광고 게재·동의 검사를 수행했다는 뜻은 아니다. 이번 예외 범위와 실제 검증을 구분한다.
- 제출 후 서버를 다시 조회해0.3.4에 빌드14가 연결되고 정식 심사 대기·TestFlight 이용 가능 상태임을 확인했다. [최종 재조회](evidence/ios-release-034-20261111/final-state.json).
- 임시 서명 키체인을 삭제하고 이전 키체인 검색 목록을 복원했다. 복구한 개인키·인증서 비밀번호·암호화 백업·복구키는 임시 디렉터리에서 제거했다.
